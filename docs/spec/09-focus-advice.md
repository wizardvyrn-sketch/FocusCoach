# 09. 中断からの復帰支援(旧: 集中切れアドバイスポップアップ)

> 状態: **確定(2026-10-03)。** 業務スタイルのヒアリングと、確認事項(U-09-1〜7)への利用者の回答を反映した。
> ヒアリングの結果、利用者の課題は「気が散る」ことではなく「割り込みで中断し、戻れずに別タスクへ流れる」ことだと分かった。
> そのため、本章の主眼を「ポップアップで注意する」から「**中断の前に文脈を退避し、戻るときに文脈を復元する**」に変更する。

## 9.1 目的

割り込み(チャット、電話、急ぎの依頼、会議の準備)で作業が途切れても、元の作業へ短時間で戻れるようにする。成功の基準は、まとまった作業(例: 開発計画書、集中時は約1.5時間)を、割り込みが無い場合の標準時間に近い時間で、その日のうちに終えられる回数が増えることとする。

## 9.2 利用者の業務スタイル(ヒアリング結果の要約)

| 観点 | 内容 | 設計への影響 |
|------|------|-------------|
| 1日の流れ | 8:30〜9:00始業、12:00から45分休憩、定時17:30、残業で20:00前後まで。会議は社内外から散発的に入り、繁忙期は1日の半分以上 | 連続した作業時間を確保しにくい前提で設計する |
| 集中しやすい時間帯 | 15:00〜定時後。昼過ぎは眠気が出ることがある | 時間帯による介入はしない。振り返りで傾向を示すだけにする |
| 割り込み | 約1時間に1回。最近はチャットが多い。後回しでよいものと、他メンバーが詰まるので早めに対応すべきものが半々 | 割り込みを「すぐ対応」と「棚上げ」に分けて扱う |
| 戻るときの困りごと | 割り込み先のタスクで関係ファイルを探すため、ウィンドウが増え、元の作業で見ていた画面が埋もれる | 復帰時に、作業用のウィンドウ配置を戻す |
| 集中が切れる流れ | 中断後に再開しようとすると、調べたことの一部を忘れており、どこまで覚えているかを調べ直すのが面倒になり、別タスクを始めてしまう | 「調べたこと」と「どこまでやったか」を手元に残す |
| 切れやすい段階 | 資料確認中と、文書を書いている途中。終盤の整えは問題ない | 資料確認と執筆のサブタスクを重点的に支援する |
| 資料確認の比率 | 作業時間の半分近く | 資料の行き来は正常な作業であり、集中切れとみなさない |
| 業務外の閲覧 | 基本的に無い | 「気が散っている」ことを検知・注意する機能は不要 |
| 今やっている対策 | Teamsを強制的に切り、音楽を聴く。必要なファイルと画面画像をデスクトップへローカルコピーしてから作業する | この手作業を、アプリの機能として置き換える |
| 常用アプリ | Outlook、Teams、ブラウザ(社内システムは SharePoint)、Word、Excel | Teams と Outlook を「割り込みアプリ」として分類する |
| モニタ | 1920×1080 ワイド1枚、または17インチのスクエアモニタを加えた2枚 | 表示要素はミニパネル内に収め、画面を占有しない |
| 介入の許容度 | 画面の隅の色や表示が変わる程度(ヒアリングの選択肢 b) | ポップアップは原則出さない |
| 嫌なこと | 作業中に作業の順序を指示されると混乱する | 「次は〜しましょう」のような指示文は出さない |
| 自己申告 | ボタンを押す運用で当面は可 | 自己申告を MVP の主な入力にする |

## 9.3 設計方針

1. **ポップアップを出さない**: 作業中の表示は、ミニパネル(S-04)の縁の色とアイコンの変化だけとする。音は鳴らさない。トースト(旧 S-11)は廃止し、復帰カード(新 S-11)は利用者の操作を起点としてだけ開く。
2. **指示しない、思い出させる**: 文面は事実の提示に限る(「中断前: ②概略仕様の確認、メモ『3章の非機能要件まで確認』」)。作業順序の指示や、休憩・姿勢の勧告は出さない。
3. **資料の行き来は正常な作業**: 作業の半分は資料確認である。そのため、SIG-1(切り替えの頻発)と SIG-5(往復)では介入しない。
4. **データは端末の外に出さない**: 画面画像、ファイル、ウィンドウタイトルは、ローカルのデータフォルダにだけ保存する(§9.8)。

## 9.4 機能

### 9.4.1 割り込み退避(⚡ボタン / F9)と、どこまでやったかのメモ(F10)

電話や声かけで片手しか空いていない場面を前提に、**1回の操作で記録が済む**ようにする(2026-10-04 改訂。レビュー R-01、R-03、R-05)。

| 操作 | 作業中 | 一時停止中(割り込み中) |
|------|--------|------------------------|
| ⚡ボタン / **F9** | **すぐ対応**: その場で一時停止(理由 `interrupt`)し、作業ウィンドウのスナップショットを取る。入力は求めない(0.12A: ボタンはしおりのアイコン +「割り込み対応」) | **出口カード**(03 §3.6)を開く。閉じると再開し、再入場ガイド(短い割り込みでは復帰カード)を出す。カードの表示中にもう一度 F9 で「完了」で閉じる(0.12A) |
| 📝ボタン / **F10** | **棚上げ**: 割り込みの内容を1行メモして棚上げリストに入れる。一時停止しない | **再開メモ**: 「どこまで」と「**次の一手**」の2行を、中断したサブタスクに付ける(どちらか1行だけでもよい。何度でも上書きできる) |

- 再開メモの「次の一手」は、再開したら最初にやること(例:「概略仕様書の第3章から読む」)。利用者自身が書くもので、ツールからの指示ではない。中断前に再開の計画を短く書くと、前の作業への注意の残りが減り、再開が速くなる(ready-to-resume plan。`prototype/review/psychology-ideas.md` I-01。2026-10-04 追加)。
- メモは、割り込みの瞬間ではなく、手が空いたとき(割り込み中・再開直後)に入力できる。再開後でも、直前の割り込みのサブタスクに付けられる。
- メモ入力は、ミニパネルとは別の小さな入力ウィンドウで行う。入力の間だけアクティブになり、Enter / Esc で閉じて、元のウィンドウにフォーカスを返す(ミニパネル本体はフォーカスを奪わない。03 S-04)。
- F9 / F10 はグローバルホットキーとして登録する。登録中、そのキーは他のアプリに届かない(例: Excel の F9 再計算)。設定で別のキーに変えられる。登録に失敗したら、ミニパネルに表示する。F8 はコンパクト表示の切り替え(03 S-04b。0.10A)に使う。F8 を登録できなかったときは、元に戻せなくならないよう、コンパクト表示をクリック透過にしない。F11 / F12 は既定で割り当てない。
- Teams の会議開始や通話を検知したときは、ミニパネルの縁の表示を変えて F9 を促す(自動では一時停止しない。F-15)。
- 音声での「どこまで」メモ(F-07)は P-6 で追加する。

### 9.4.1a 離席・ロック・スリープから戻ったとき(2026-10-04 追加。R-04、R-16、R-17)

ボタンを押す余裕がないまま席を離れた場合でも、戻ったときに1クリックで割り込みとして記録できるようにする。

| 検知 | 記録 | 戻ったとき |
|------|------|-----------|
| 無操作(アイドル)が `away_prompt_sec`(既定300秒)以上 | アイドル区間として記録する(作業時間から除く) | ミニパネルに「離席 N 分を割り込みとして記録しますか? [はい] [いいえ]」を出す |
| 画面ロック(Win+L) | 一時停止(理由 `lock`)を自動で記録する | 同上(はい → 理由を `interrupt` に変更) |
| スリープ / 休止状態 | 一時停止(理由 `sleep`)を自動で記録する | 同上 |
| リモートデスクトップの切断(外から業務PCへ接続して使っている場合) | 一時停止(理由 `remote`)を自動で記録する | 同上 |

- [はい] を選ぶと、その区間を**割り込み**に分類し直し(イベント `away_reclassified`)、復帰カードを出す。[いいえ] または無視した場合は、元の分類(アイドル・ロックなど)のまま残す。
- 問いかけは縁の表示と同じくポップアップにせず、ミニパネルの中に出す。一定時間(`resume_card_auto_close_sec`)で畳む。

### 9.4.2 復帰カード(新 S-11)

「すぐ対応」から作業を再開するとき(一時停止の解除時)に、ミニパネルから展開する小さなカードとして表示する。フォーカスは奪わない。表示する内容は次のとおり。

- **次の一手**(再開メモの2行目)。カードの一番上に大きく出す
- 中断前のサブタスクと、中断していた時間(例:「中断 0:23」)
- どこまでやったか(再開メモの1行目、`resume_note`)
- このサブタスクで、ここまでに確認した資料の一覧(F-06 のアクセス記録)と、作業トレイ(§9.4.3)の内容。クリックで開ける
- 操作ボタン:
  - **[作業画面に戻す]**: 中断前のスナップショットにあった作業ウィンドウを、元の配置で前面に戻す。中断中に開いたウィンドウは**最小化する**(閉じない。F-03 と同じ扱い)。どのウィンドウを最小化するかの判定は、Core の純粋関数として実装する
  - **[そのまま再開]**: ウィンドウ操作をしない

カードは再開から一定時間(既定60秒)たつか、作業ウィンドウで入力が始まったら自動で畳む。

### 9.4.2a 棚上げリストとあとでやること

棚上げした割り込みは、タスク終了時(S-06 の後)と振り返り(S-07)で一覧として表示する。Outlook のタスクなど外部への書き出しは行わない。

0.12A: 出口カードで「あとでやることが残る」を選んだものは、**あとでやること**(S-12)としてローカルの DB に保存し、タスクをまたいで残す(完了にするか消すまで)。ミニパネルの件数・一覧・トレイのメニュー・振り返りに出す。期限の知らせは区切りでだけ行い、作業の途中には出さない(区切りでの知らせと、F10 の棚上げの統合は 0.13A)。

### 9.4.2b 出口カードと再入場ガイド(2026-10-29 追加。0.12A)

技術系の商品開発の現場で、営業・現場エンジニア・社内メンバーからの問い合わせで頻繁に中断し、対応で開いたウィンドウが残ってノイズが多く、再開の心理的なハードルが高い、という状況への対策。

- **割り込みを閉じる儀式**(出口カード): 終わっていない問い合わせは注意を引き続ける(注意残余)。「完了」か「あとでやること(1行・期限)」として外に預けてから戻ると、頭に残りにくい。何も書かずに Enter で閉じられるようにし、手間を増やさない。
- **再入場ガイド**: 元の作業の実物のウィンドウを前に出し(最も強い思い出しの手がかり)、短い間(既定40秒)を置いて気持ちを切り替え、時間で作業に戻る(「いつ戻るか」を決めなくてよい)。その間の過ごし方は本人に任せる。急かさない見せ方、[+30秒]・[今すぐ戻る]、入力中はフォーカスを移さない、短い割り込みでは出さない、を守る。
- **中断の心理的な障壁を下げる**: ボタンは「中断」ではなく、しおり +「割り込み対応」。1回押すだけで、覚えておくのはツールの役目であることを文言で示す。
- 配布先: 同じ現場の新しく入ったメンバーも、別の端末で説明なしに使う。初期設定は一般的なもの(カテゴリは「割込み作業」だけ、ガイド40秒)、文言は説明なしで分かる言葉にする。
- 詳細と心理学的な評価: [../../prototype/review/design-0.12A-interrupt-closure.md](../../prototype/review/design-0.12A-interrupt-closure.md)。

### 9.4.3 作業トレイ(調べたことを手元に置く)

利用者が今手作業で行っている「必要なファイルや画面画像をデスクトップに集める」作業を置き換える。

- ミニパネルの「📥トレイ」へ、ファイルのドラッグ&ドロップ、クリップボードの画像(Win+Shift+S で切り取ったもの)の貼り付け、テキストの貼り付けができる。
- 保存先はローカルのタスク実行ごとのフォルダとし、外部には送らない。ファイルは既定で**ショートカット(参照)**として保存し、指定したものだけをコピーする(SharePoint 上の文書を無断で複製しない)。2026-10-03 時点で、ローカルコピーを制限する社内規定は無い。
- トレイの各項目には、追加した時点のサブタスクと1行の注記を付けられる。
- 復帰カードと資料ランチャー(S-05)から開ける。タスク終了時に、トレイの中身を残すか削除するかを選ぶ。

### 9.4.4 周辺表示(ミニパネルの縁の色)

| 状態 | 表示 | 条件 |
|------|------|------|
| 通常 | 既定色 | — |
| 目安超過 | 柔らかい琥珀(強い橙・赤は使わない。03章 §3.4.1) | サブタスクの目安を超えた(F-05 と同じ) |
| 割り込みアプリに滞在中 | 青 | Teams / Outlook などの割り込みアプリが前面のまま `interrupt_app_dwell_sec`(既定90秒)以上経過した。⚡ボタンを強調表示する |
| 中断中 | 灰青 | 一時停止中 |

色だけに頼らず、アイコンも変える(色覚への配慮)。表示の変化は利用者の操作を妨げない。`interrupt_app_dwell_sec` と色の組み合わせは、実利用(P-9)で調整する。

### 9.4.5 開始時の Teams 応答不可の案内

作業の開始時(S-02 で「集中を始める」を押した後、S-03 開始演出の前)に、「Teams の状態を『応答不可』にしますか?」という案内を1行で表示する。アプリは Teams の状態を切り替えない(公開APIが無いため。U-05-4)。案内は設定で非表示にできる。

### 9.4.6 画面共有・録画への配慮(2026-10-04 追加。R-20)

利用者は Teams で画面共有を行う。ミニパネル・コンパクト表示・復帰カード・メモ入力ウィンドウ・手順エディタには、プロジェクト名やメモ(顧客名を含みうる)が出るため、`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` で画面共有・録画・スクリーンショットに映らないようにする。この設定が効かない環境(古い Windows など)では、会議を検知している間ミニパネルを1行表示に折りたたむ。

## 9.5 集中シグナルの採否

| ID | シグナル | 採否 | 理由 |
|----|---------|------|------|
| SIG-7 | 自己申告(⚡割り込みボタン) | **MVP** | 利用者が「当面は可」と回答。誤検知が無い |
| SIG-2 | 割り込みアプリに長く滞在している | **MVP**(周辺表示のみ) | 割り込みの多くは Teams のチャット。押し忘れを補う |
| SIG-3 | アイドル | **MVP**(既存の F-15 のまま) | 離席の検知に使う |
| SIG-4 | サブタスクの目安を超過した | **MVP**(既存の F-05 のまま) | 色を変えるだけ |
| SIG-1 | 切り替えが頻発している | 記録のみ | 資料の行き来は正常な作業。振り返りの指標(F-11)に使う |
| SIG-5 | 同じ資料の間を行き来している | 記録のみ | 同上 |
| SIG-6 | 休憩なしで長時間続けている | 不採用(F-05 のポモドーロ設定で代替) | 休憩の勧告は求められていない |
| SIG-8 | 時間帯・疲労 | 不採用 | Outlook の予定表は使用不可。時間帯の傾向は振り返りで示すだけにする |
| SIG-9 | マイクの周囲音量(会話中の判定のみ、録音しない) | 将来の候補(既定OFF) | 利用者は可と回答したが、設備の動作音が日常的に入るため誤検知しやすい |
| — | Webカメラ | 不採用 | 普段使っていない |
| — | Outlook の予定表 | **使用禁止** | 会議案内に顧客名が含まれる |

## 9.6 割り込みアプリの分類

- 既定の割り込みアプリ: `ms-teams.exe`(新 Teams)、`Teams.exe`(旧 Teams)、`OUTLOOK.EXE`(メール画面)。設定(S-10)で追加・削除できる。
- 割り込みアプリはオフタスクとして数えるが、振り返りでは「割り込み対応」として、ほかのオフタスクと分けて表示する。
- タスクの資料としてアクセス記録に載った Outlook のメールや Teams のファイルは、オンタスクとして扱う(F-11 のタスクのウィンドウの定義に従う)。

## 9.6a リモートデスクトップ(2026-10-04 追加。R-46)

| 使い方 | 扱い |
|--------|------|
| (a) 業務PCから、サーバーなど別の PC へ接続する | サーバー管理の業務で発生するもので、本ツールの管理対象(メイン業務)から**除外**する。`mstsc.exe` は通常のアプリとして扱い、特別な判定はしない。必要なら利用者が「タスクで使うアプリ」に指定できる(05 F-02) |
| (b) 自宅などから業務PCへ接続し、業務PCの上で FocusCoach を使う | FocusCoach は接続先(業務PC)のセッションで動く。ホットキーは接続先に届くので、そのまま使える。**接続が切れた区間は離席として一時停止(理由 `remote`)**にし、再接続したときに §9.4.1a の問いかけを出す |

## 9.7 効果の測定(振り返り S-07 に追加)

| 指標 | 定義 |
|------|------|
| 割り込み回数 | ⚡ボタンの押下回数(すぐ対応 / 棚上げ別)と、SIG-2 で周辺表示した回数 |
| 割り込みによる中断時間 | 理由が `interrupt` の一時停止区間の合計 |
| 復帰時間 | 一時停止の解除から、作業ウィンドウでの最初の入力までの時間 |
| 割り込みを除いた所要時間 | 総時間 − 中断時間 − アイドル時間。割り込みが無い場合の標準時間と比べる |
| 同日内の完了 | 開始した日のうちに終えたかどうか。後日に持ち越した実行(`suspended` を経たもの)は「いいえ」とし、作業した日数も表示する |

イベントとして `interrupt_marked`(種類)、`interrupt_note_added`、`interrupt_deferred`、`away_reclassified`、`resume_card_shown`、`workspace_restored`(戻したウィンドウ数、最小化した数)、`tray_item_added` を JSONL に記録する([08](08-debug-logging.md) §8.3)。

## 9.8 外部送信とLLM

- MVP では LLM を使わない。表示する文面はすべて定型文とし、実データを埋め込んで表示する。
- 画面画像、ファイル、ウィンドウタイトル、URL を、一般の Web サービス(検索エンジン系、汎用のアップロードサイトなど)へ送ることは行わない。
- 将来 LLM を使う場合(例: `resume_note` とトレイの内容から、中断前の状況を要約する)は、オプトインとし、送信先は社内のセキュリティ規定で許可されたサービス(利用者の会社が契約している Claude の Team プラン)に限る。Claude への送信は現時点で支障が無い見込みだが、どの情報を送るかは、実際にどんなデータが発生するかを見てから決める(U-09-4)。
