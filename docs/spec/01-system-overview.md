# 01. システム概略

> 状態: 初版(2026-10-03)

## 1.1 目的

システム/ソフトウェア開発の担当者が、プロジェクトごとに繰り返し発生する定型業務を**集中して短時間で終える**ためのコーチングツールを提供する。
対象とする定型業務の例は「開発計画書の作成」である。

定型業務には次の特徴がある。

- 1つのメインタスクが、何段階かのサブタスクに分かれる(例: 見積書の確認 → 概略仕様の確認 → 担当作業メンバの確認 → スケジュールの確認 → 本文作成)。
- 各サブタスクでは、前工程で作られた資料を参照する。資料はファイルサーバ、Webの管理システムなどに散らばっている。
- 同じ種類のタスクがプロジェクトをまたいで何度も発生する。そのため過去の実績が次回のガイドとして使える。

## 1.2 解決したい課題

| 課題 | 本ツールでの対応 |
|------|------------------|
| 作業中に他のウィンドウや通知に気を取られ、集中が途切れる | タスク専用ワークスペース(他ウィンドウの一時最小化)、集中BGM、集中切れアドバイス |
| 参照資料がどこにあったか探す時間がかかる | タスク中に開いたフォルダ・ファイル・URLを自動記録し、次回はサブタスクごとにワンクリックで開けるようにする |
| 毎回どれくらい時間がかかっているか分からず、改善できない | サブタスク単位の時間記録と、前回・過去平均との比較 |
| 作業の経緯やメモが残らない | テキスト/音声の作業メモ(音声はテキスト化) |
| 定型業務がおっくうで着手が遅れる | 開始・完了時の演出、自己ベストの表示などの動機づけ |

## 1.3 基本コンセプト: 「実績 → ガイド → 記録 → 比較」のループ

```
 ┌──────────────┐   過去の同種タスク実績     ┌──────────────┐
 │ 振り返り・比較 │ ───────────────────────▶ │ 開始前ガイド   │
 │ (改善ポイント) │                          │ (手順・目安時間・ │
 └──────▲───────┘                          │  前回の資料)    │
        │                                  └──────┬───────┘
        │ 終了                                     │ 開始(演出)
 ┌──────┴───────┐                          ┌──────▼───────┐
 │ ワークスペース  │ ◀─────────────────────── │ 集中作業       │
 │ 復元           │                          │ (タイマー・BGM・ │
 └──────────────┘                          │  自動記録・メモ) │
                                           └──────────────┘
```

使うほど過去の実績がたまり、ガイドと比較の精度が上がる。

## 1.4 想定ユーザー・利用シーン

- **ユーザー**: システム/ソフトウェア開発の担当者。1人で利用する。チームでの共有はMVPの対象外。
- **端末**: 業務用のWindows PC。管理者権限が無い前提で設計する。
- **シーン**: 自席またはリモートワーク中に、定型ドキュメントの作成・確認などのまとまった作業を30分〜数時間かけて行う。途中でWeb会議や問い合わせによる中断が入りうる。

## 1.5 スコープ

### MVPの対象

- タスク種別とサブタスク定義の管理。後からの統合・再分類を含む
- 過去実績に基づく開始前ガイド
- タスク用ワークスペースの切り替えと復元
- 作業中に開いたフォルダ・ファイル・URLの自動記録
- タイマー、集中BGM、開始・終了の演出
- テキストメモ、音声メモ(録音と、ローカルでのテキスト化)
- 終了後の振り返り(前回・過去平均との比較、集中度の推移)

### 中断からの復帰支援(P-8)

- 割り込みによる中断からの復帰支援(割り込み退避、復帰カード、作業トレイ。[09-focus-advice.md](09-focus-advice.md))

### MVPの対象外

- 複数ユーザーでのデータ共有、チームダッシュボード、上長への報告
- 他人の監視を目的とする利用。記録はあくまで本人の振り返りのためのもの
- 管理システム(Redmine、Backlog など)とのAPI連携による自動登録。将来の拡張候補
- macOS / スマートフォン

## 1.6 用語定義

| 用語 | 定義 |
|------|------|
| タスク種別 | 同じ種類の定型業務のまとまり。例:「開発計画書作成」。過去実績を集計する単位になる。後から統合・再分類できる |
| サブタスク定義 | タスク種別に属する作業ステップのテンプレート(名前と順序)。例:「見積書の確認」 |
| タスク実行 | あるタスク種別を1回実行した記録。開始時刻・終了時刻・プロジェクト名などを持つ |
| サブタスク実行 | タスク実行の中で、各サブタスクを行った記録。開始時刻・終了時刻と状態(完了/スキップ)を持つ |
| ワークスペース | タスク実行中の画面状態。開始時に元のウィンドウを最小化し、タスク中に開いたウィンドウだけで作業する |
| アクセス記録 | タスク実行中に開いたフォルダ・ファイル・URLの記録。その時点のサブタスクに紐づける |
| 資料ランチャー | 過去のアクセス記録から、サブタスクごとの参照資料をワンクリックで開けるようにした一覧 |
| 作業メモ | タスク実行中にユーザーが残すメモ。テキストと音声がある |
| 集中指標 | アクティブなウィンドウ・アイドル時間・切り替え回数から算出する集中度の目安。定義は [05-functions.md](05-functions.md) F-11 を参照 |
| オンタスク / オフタスク | 前面にあるウィンドウがタスクに関係するかどうかの区分 |
