# 06. UX仕様

> 状態: 初版(2026-10-03)

## 6.1 UX原則

1. **始めるまでの摩擦を最小にする**: ホットキー → 種別を選ぶ → 「集中を始める」、の**3操作以内**で作業に入れるようにする。前回の設定(残すアプリ、BGM)を引き継ぐ。
2. **作業中は邪魔をしない**: 作業中にモーダルダイアログを出さない。フォーカスを奪わない。通知は控えめにし、閉じやすくする。
3. **記録は自動、入力は任意**: 時間とアクセスは自動で記録する。メモと理由の入力は任意にし、入力しなくても振り返りが成り立つようにする。
4. **責めずに、次の一手を示す**: 「集中できていません」のような評価ではなく、「次回はここを短縮できそう」と具体的な提案をする。
5. **小さな達成を見える化する**: サブタスクの完了、前回比の短縮、自己ベスト、連続実行を演出で示す。
6. **振り返りは30秒で読める**: 要点を3つ以内に絞る。詳細は展開したときだけ出す。
7. **自分のためのデータであると明示する**: 記録対象を常に確認でき、いつでも削除できるようにする。

## 6.2 ユースケース

### UC-1 初めての種別で作業する

1. ホームで「新しいタスク」を選び、名前「開発計画書作成」とプロジェクト名を入力する。
2. サブタスクを思いつく範囲で入力する。入力しなくてもよく、作業中に追加できる。
3. 「集中を始める」→ 作業 → 終了。終了時に「この手順を種別のテンプレートとして保存しますか?」と尋ねる。
4. 振り返りには比較対象が無いため、「次回からこの記録と比較されます」と伝え、今回の内訳を示す。

### UC-2 2回目以降(主シナリオ)

1. 種別を選ぶと、前回の実績、目安時間、前回の資料が並んだ計画が表示される。
2. 目標時間(初期値は前回の95%)を確認して、「集中を始める」を押す。
3. 開始時の演出の後、各サブタスクでランチャーから資料を開いて作業する。サブタスクを完了するたびに小さな演出が出る。
4. タスクを終了したら完了演出を出し、ウィンドウを整理して元の画面に戻る。続けて振り返りで前回比と改善ポイントを示す。

### UC-3 途中で会議や問い合わせが入る

1. 一時停止して、理由に「会議」を選ぶ。会議のウィンドウが前面に出たことを検知して、一時停止を提案することもある。
2. 一時停止中はワークスペースを維持したまま、通常どおり他のアプリを使える。
3. 再開すると、中断前に作業していたサブタスクと、最後のメモを表示し、作業に戻りやすくする。

### UC-4 終了し忘れ・PCのスリープ

- 長時間のアイドルを検知したら、戻ったときに「離席していた区間を一時停止扱いにしますか?」と確認する。
- 翌日などにアプリを起動したとき、`running` の実行が残っていれば復帰ダイアログを出す(F-16)。

### UC-5 種別を整理する

- 「計画書作成」と「開発計画書作成」が重複していたら、統合候補として提案する。ユーザーは統合し、サブタスク名の対応づけを確認する。誤って統合しても取り消せる。

### UC-6 音声で作業記録を残す

- ホットキーで録音を始めて「見積の工数、前回より2割増し。理由は○○」と話し、もう一度押して止める。数十秒後にテキスト化され、振り返りに表示される。

## 6.3 演出のトーン

- 目指すのは、業務ツールとして**落ち着いているが、達成感がある**こと。派手すぎる演出は職場では逆効果になりうるため、既定は控えめにする。
- 効果音は短く、ヘッドセットで聞いて不快でない音量にする。会議中の誤再生を防ぐため、通話中は鳴らさない。

## 6.4 コーチングの文面ガイドライン

| 避ける表現 | 推奨する表現 |
|------------|--------------|
| 集中力が低下しています | 25分経過しました。ここで2分休むと後半が楽になりそうです |
| 前回より12分遅いです | 「概略仕様の確認」が前回より+12分。資料が増えていたかもしれません |
| 切り替えが多すぎます | Outlookへの切り替えが8回ありました。次回はメール確認をタスクの前後に回すのも手です |

- 数値には必ず比較の基準(前回/中央値)を添える。
- 原因は断定せず、「〜かもしれません」とする。提案は1つに絞る。

## 6.5 継続利用の仕組み

- 自己ベストと前回比の短縮を表示する。
- 種別ごとの実行回数と、所要時間の推移グラフを示す。下がっていく様子が見えるようにする。
- 実績がたまるほどガイドが賢くなることを伝える(例:「実績5件 — 目安時間の精度: 高」)。
