# 0.13A 英語表示の切り替え(多言語化)— 設計案

> 状態: **0.13A で実装(2026-11-03)。** 利用者の回答(§7 は推奨案)で進めた。実装の結果は §8 に記録する。
> 入力: 利用者の要望「GitHub での公開を検討したい。現在は日本語版のみなので、英語に表示を切り替えられる機能を入れたい。ファンクションキーなど特定のキーでの切り替えも検討して」。
> 関係する仕様: 03(画面)、07(技術)、08(ログ)。公開の手順そのものは別(§6)。

## 0. 要望と解釈

| # | 要望 | 解釈 |
|---|------|------|
| L1 | 英語で表示できる | 画面に出る文言(ボタン・ラベル・ダイアログ・案内・振り返り・トレイ・吹き出し)を日本語 / 英語で切り替えられるようにする。**利用者が入力した内容(タスク名・手順・メモ・カテゴリ名・あとでやること)は翻訳しない** |
| L2 | 特定キーで切り替え | 実行中でも1操作で切り替えられる。ただし後述のとおり、ファンクションキーの単独割り当ては衝突の害が大きい。**キー・ボタン・トレイのメニューの3つ**から切り替えられるようにする |
| L3 | GitHub 公開 | 英語の読み手を想定する。画面だけでなく、README・配布物の説明も英語版が要る(§6) |

## 1. 現状(調べた結果)

- 日本語の文字列は、コードと XAML に **約240行**(MainWindow.xaml 35 / MainWindow.xaml.cs 60 / ダイアログ 26 / 出口カード 26 / CoreHost 14 / Params 13 / Reentry 10 / その他)。すべて直書き。
- **Core(画面を持たないプロジェクト)にも画面に出る日本語がある**: ガイド・比較の文(「…は中央値より 3分 長くなりました」)、手順の検証エラー(「2行目: 名前を入れてください」)、手順の要約、時間の書き方(「1時間20分」)、振り返りの文面、指標の名前。
- 表示と無関係の日本語もある: ログ・例外メッセージ(`CommandRejectedException`)、シナリオのコマンド、除外ルールの正規表現(`シークレット`)。これらは翻訳の対象にしない(ログは英語に統一する方向)。
- UI 自動操作・確認スクリプトが、ボタンの**日本語の表示名**で押している(`AutomationProperties.Name`)。文言を切り替えると壊れる。
- 書体は `BIZ UDPGothic` 先頭(英数字も出るが、英語には幅が広すぎて間延びする)。

## 2. 方式

### 2.1 文言の持ち方 — キー付きの辞書(JSON)+ 小さな `Loc`

| 案 | 内容 | 判断 |
|----|------|------|
| A. .resx(標準のリソース) | WPF の標準。サテライトアセンブリ | 自己完結の発行・クラウド(Linux)での型チェックと相性が悪い。ビルドの手間が増える |
| **B. JSON の辞書 + `Loc`(推奨)** | `strings.ja.json` / `strings.en.json` をアセンブリに埋め込み。`Loc.T("exit.title")`、`Loc.T("followup.badge", n, due)` | Core にも置ける(画面の部品に依存しない)。テストしやすい。**貢献者が JSON を足すだけで言語を増やせる**(OSS 向き) |
| C. 日本語を鍵にする(`T("割り込み対応")`) | 見た目は楽 | 日本語の言い回しを直すたびに鍵が変わり、英語側が壊れる。不採用 |

- キーは `画面.要素` の形(例: `main.start`、`exit.followup`、`review.total`)。値は `string.Format` 形式(`{0}`)で、**複数形・語順は文ごとに英語側で自由に書ける**(「3 items」「1 item」は `…one` / `…other` の2キー)。
- 辞書に無いキーは、英語 → キー名の順で補い、**実行を止めない**(欠けが画面に「⟦main.start⟧」と出るので気づける)。
- `Loc` は Core に置く(状態は `Language`。切り替えのイベントを持つ)。Core の文(ガイド・検証エラー)も `Loc` 経由にする。**Core は文字列ではなくキーと値を返す形に寄せる**(例: `StepError(Row, Kind)` を返し、文章にするのは表示側)— 大きく直す場合は 0.13A では文を `Loc` 経由にするだけにして、構造化は後回しにしてよい。

### 2.2 切り替えをその場で反映する

- XAML は `{loc:T main.start}`(自作のマークアップ拡張。`Loc` の変更通知に束縛)にして、**ウィンドウを作り直さず**に文字が替わる。
- コードで作るウィンドウ(メモ・出口カード・ダイアログ・一覧)は、開くたびに今の言語で作る。開いている間に替えたものは閉じるまで元の言語のままでよい(短時間しか開かないため)。
- ミニパネルの `Render`・コンパクト表示・トレイのメニュー・ツールチップは、切り替えのイベントで作り直す。

### 2.3 言語の決め方と保存

- 設定 `Language`: `auto`(既定)/ `ja` / `en`。`auto` は OS の表示言語が日本語なら `ja`、それ以外は `en`(**GitHub から来た人は英語で始まる**)。
- 切り替えたら `auto` ではなくその言語を保存する(次の起動でも同じ)。「OS に合わせる」に戻す操作は設定画面ができてから(それまでは settings.json の `Language` を `auto` にする)。
- 日付・時刻・数の書き方も言語に合わせる(`1:20:00` はそのまま、日付は `10/30` ↔ `Oct 30`、「1時間20分」↔「1h 20m」)。

### 2.4 注意が要る箇所

| 箇所 | 問題 | 対応 |
|------|------|------|
| **既定のカテゴリ「割込み作業」** | DB に名前そのものが保存されている | 内部では固定の名前(`割込み作業`)を既定カテゴリの目印にし、**表示のときだけ**言語に応じて「割込み作業」/「Interruptions」にする(入力して作った名前はそのまま)。DB の変更は不要 |
| **誘いかけの一言 `ReentryGuideMessage`** | 既定値が日本語で settings.json に入る | 既定は `null`(未設定)にし、未設定なら言語ごとの既定文(`Focus on your task for {sec} seconds`)を使う。過去に保存された日本語の既定文と同じ値も「未設定」として扱う |
| **除外ルールの正規表現**(`InPrivate|シークレット|Incognito`) | 表示ではないが、ブラウザの表示言語に依存 | 変えない(英語のブラウザでも `InPrivate|Incognito` で効く)。文言ではないので辞書に入れない |
| **UI 自動操作・確認スクリプト** | 日本語の表示名で押している | 要素に **`AutomationProperties.AutomationId`**(言語に依存しない名前)を付け、スクリプトはそれで探す。表示名(`Name`)は言語に合わせて翻訳する(アクセシビリティのため) |
| **文の長さ** | 英語は日本語より横に長い(ボタン・ミニパネル・コンパクト表示) | 書体を言語ごとに切り替える(英語は `Segoe UI Variable` 等)。ボタンは最小幅 + 折り返し。**疑似長文(長めの英語)**で `ui_render_probe` を回して崩れを確認する |
| **ホットキーの表示** | 「割り込み対応  F9」のように文言にキーが入る | キーの部分は文言から分け、設定のキーから組み立てる(設定でキーを変えても文言が嘘にならない) |

## 3. 切り替えの操作(L2)

**結論: ファンクションキーの単独割り当ては勧めない。** 理由は、(1) F7 は Word のスペルチェック、F6 はブラウザのアドレス欄への移動、F11・F12 はブラウザの全画面・開発者ツールなど、**業務アプリが使うキーを奪うとその間そのアプリで使えなくなる**(グローバルホットキーは他のアプリに届かない。F8〜F10 でも既にこの懸念があり、W-06 で確認予定)、(2) 言語の切り替えはまれな操作で、貴重なキーを占有する価値が低い、(3) 実行中のミニパネルはフォーカスを奪わない作りなので、「ウィンドウがアクティブのときだけ効くキー」では作業中に効かない。

| 操作 | 内容 | 既定 |
|------|------|------|
| **タイトル帯のボタン** | `日本語 / EN` を表示する小さなボタン(▭ – ✕ の左)。押すたびに切り替わる。現在の言語がボタンの文字 | あり |
| **トレイのメニュー** | `Language / 言語` → 日本語 / English。**メニューの見出しは、どの言語でも「Language / 言語」の併記**にする(言語を間違えて切り替えても戻れる) | あり |
| **グローバルホットキー** | 修飾キーつき(既定案 **Ctrl + Alt + F8**)。押すたびに ja ⇄ en。他のアプリのショートカットと衝突しにくい組み合わせにする | あり(設定で変更・無効にできる)。登録に失敗したら、今までのホットキーと同じく画面に出す |

- 修飾キーつきの登録は、今のホットキー処理(`RegisterKey`)に修飾キーの引数を足すだけで済む。
- 切り替えたとき、トレイの吹き出しやダイアログは出さない(画面の文字が替わること自体が確認になる)。ログに `language changed ja->en` を1行出す。
- 作業の状態・タイマー・記録には一切影響しない(表示だけを替える)。

## 4. 実装の範囲と順序

**0.13A(この設計の範囲)**

1. `Loc`(Core)と辞書(`strings.ja.json` / `strings.en.json`)、キー欠けの補い、`Language` 設定、`auto` の判定。
2. 文言の移行: XAML → コードビハインド → ダイアログ・出口カード・ガイド・一覧 → トレイ・吹き出し → Core(ガイド・比較・手順の検証・振り返り・時間の書き方)。**移行は画面ごとに進め、都度テストと描画で確認する。**
3. 切り替えの操作: タイトル帯のボタン、トレイのメニュー、グローバルホットキー。
4. 周辺の直し: 既定カテゴリの表示の対応、誘いかけの一言の既定、書体の切り替え、`AutomationId` の付与(確認スクリプトもそれで探す)。
5. 日付・時間の書き方を言語に合わせる。

**テスト(自動)**
- 辞書のキーが ja・en で同じであること、`{0}` の数と番号が同じであること(欠けや食い違いの検出)。
- **画面に出る日本語の直書きが残っていないこと**を調べるテスト(辞書以外のソースで、日本語を含む文字列リテラルを走査。ログ・例外・シナリオ・正規表現は許可リストで除外)。移行の取りこぼしを防ぐ。
- Core の文(ガイド・比較・検証エラー・時間の書き方)を、ja・en 両方でテスト。
- 実アプリで切り替えを自動操作し、ボタン名・ラベルが替わること、再起動後も言語が残ることを確認。`ui_render_probe` で、英語(と疑似長文)の全画面を PNG にして崩れを確認。

## 8. 実装の結果(2026-11-03、0.13A)

### 利用者の回答

§7 の Q1〜Q4 はすべて **推奨案**(ボタン + トレイのメニュー + 修飾キーつきホットキー Ctrl+Alt+F8 / 既定は OS に合わせる / 英語の文言は私が書いて見直しを依頼 / 0.13A は画面の英語化だけで、英語の README などは 0.14A)。

### 設計から変えた点・決めた細部

- 辞書は約240キー(`src/FocusCoach.Core/Strings/ja.json`・`en.json`)。書式は `string.Format`(`{0}`、`{1:0.##}`)。複数形のキー分けは、今の文言に複数形が出てこないため見送った(必要になったら `…one` / `…other` を足す)。
- 辞書の引き先は Core の `Loc`。XAML の `{loc:T キー}` は `LocSource`(`INotifyPropertyChanged` の `Item[]`)への束縛。キーに `.` を使っても動くことを確認した。
- 言語が替わったときは `Loc.Changed` → `MainWindow.ApplyLanguage()` で、コードで設定している文言(割り込みボタン・縁の文言・復帰カード・トレイ・コンパクト表示・手順の出どころの文・件数)をすべて作り直す。開いているメモ・出口カードなどは、閉じるまで元の言語のまま(短時間しか開かないため)。
- 手順の出どころの文は、文ではなく「文の作り方」(`Func<string>`)を持って、言語が替わったとき作り直す。
- 書体: 英語は `Segoe UI Variable Text, Segoe UI, BIZ UDPGothic, …`、日本語は今までどおり。`UiFont` を `DynamicResource` にして差し替える。
- トレイのメニューは「Language / 言語」の下に 日本語 / English(現在の言語に ● を付ける。メニューの左の余白を出していないため)。
- ホットキーは `RegisterKey(h, id, vk, modifiers)` に修飾キーの引数を足した。登録に失敗したら、今までのホットキーと同じく画面に出す(`hotkey.failed`)。ツールチップの「Language / 言語(Ctrl+Alt+F8)」は、登録できたときだけキーを出す。
- 区切りの「・」は、英語でも自然な「·」に替えた(日本語でも見た目はほぼ同じ)。振り返りの箇条書きは「• 」。
- 開発者向けの説明(`Params` の説明)は、画面に出ないので英語にした。ログ・例外のメッセージは、もともと英語が中心(画面に出る一部の例外メッセージ `err.no_task` は辞書へ)。
- 確認スクリプトは `AutomationId`(`StartButton`・`InterruptButton`・`LangButton`・`ExitOkButton`・`Dialog_Cancel` など)で探す。表示名は言語で替わる。`prototype/ui_close_flow_probe.ps1` は 0.12A のダイアログ置き換えから日本語の表示名・Win32 のメッセージボックス前提のままで、そのままでは動かない。

### 確認したこと

- テスト166件(辞書の ja / en のキー一致・プレースホルダ一致・書式の妥当性、英語に日本語が混ざらないこと、**日本語の直書きの走査**(わざと混ぜて検出することも確認)、`Loc.Resolve`、Core の文を英語で、既定カテゴリの表示と保存名の往復、誘いかけの一言)。
- 実アプリの自動操作(UI Automation と WM_HOTKEY id 4。保存先は隔離): `JA` → ボタンで `EN`(開始準備・タイトル帯のボタンの名前・ツールチップが替わる)→ ホットキーで `JA` → `EN`。作業中(英語)の割り込みボタン・次へ・タスク完了、割り込み対応中(「Back to work」)に言語を替えても状態が変わらない、出口カード(英語)・再入場ガイド(英語)・閉じる確認(英語。ボタンは `Don't close` / `End and close` / `Suspend and close`)。`settings.json` の `Language` が `en` になり、再起動後も英語で始まる。ログに `language changed ja->en` が出る。
- 見た目: `prototype/ui_render_probe <出力> en` / `ja`(言語の引数を追加)で、全画面を PNG にして確認(英語で文字が崩れない。出口カードの「Pick a date」は折り返したので「Date」に短くした)。
- 未確認(利用者の実機で): 実際の Ctrl+Alt+F8 キーでの切り替え、トレイのメニュー(Language / 言語)の見た目と操作、英語の自然さ(文言の見直し)、より長い英語での崩れ、2枚のモニタ。

## 9. 追記(2026-11-03、0.14A)

- **言語の前提(利用者の決定)**: 利用者は自分のメインの言語だけで使う。日本語の利用者は日本語で入力する(英語が混ざることはある)。英語の利用者は英語だけ。→ 英語の書体の日本語の代替(BIZ UDPGothic)は、念のため残すだけで、混在を前提にした調整はしない。切り替えのボタン・ホットキーは、最初の設定や、言語の違う人に画面を見せるとき用。
- コードレビューで見つけた点(0.14A で修正): 作業中に言語を替えると、隠れている開始準備の部品まで作り直していた(再開候補の走査が、実行中の記録を「途中で終了」と拾う)→ 作業中は作り直さず、開始準備に戻るときに作る。2つ目の起動の予備の案内が、保存した表示言語ではなく OS の言語だった → 設定を読む。
