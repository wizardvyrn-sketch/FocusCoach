# 0.12A〜 割り込みの「出口」とあとでやること — 設計

> 状態: **0.12A で実装(2026-10-29)。** §8 の確認事項は、利用者の回答(§10)で決まった。**画面の文言は「宿題」ではなく「あとでやること」**(本文の「宿題」は設計時の呼び名)。実装で設計から変えた点は §10 に記録する。
> 入力: 利用者の要望「技術系の商品開発現場で、営業・現場エンジニア・社内メンバーからの問い合わせで作業が頻繁に中断する。割り込み対応でウィンドウが増え、ノイズが多く、再開の心理的なハードルが高い」。前回の提案(①〜⑦)のうち **③ 出口 + ⑥ 宿題リスト** を採用。あわせて「中断ボタンにアイコンを入れ、中断すること自体の心理的な障壁をなくす」。
> 関係する仕様: 03 S-04 / S-11、04 データモデル、05 F-15、09 §9.4.1・§9.4.2・§9.4.2a。心理学の背景は `docs/review/psychology-ideas.md`。

## 1. 心理学から見た評価

### 1.1 D3「40秒で元の作業へ」のガイド

**結論: 良い案。** 効く理由が複数ある。ただし「急かされる」「まだ終わっていないのに切り替えられる」と逆効果になるので、§1.1.2 の手当てを入れる。

#### 1.1.1 効く理由

| 効き目 | 説明 | 根拠 |
|--------|------|------|
| 元の作業を思い出す手がかり | 元の作業の**実物のウィンドウ**を目の前に出すのが、一番強い思い出しの手がかりになる。メモの文字よりも、見ていた画面のほうが「どこまで考えていたか」を早く呼び戻す | 目標の記憶は手がかりで呼び戻される(Altmann & Trafton 2002, memory for goals) |
| 気持ちの切り替えの時間 | 問い合わせ対応(特に営業・現場からの急ぎ)の後は、緊張や焦りが残る。すぐに細かい開発作業に入るより、短い間を置いたほうが落ち着いて入れる | 短い休憩で注意が回復する。40秒の短い休憩(緑の景色を見る)で、その後の注意課題の誤りが減った報告がある(Lee ら 2015。小規模な研究で、再現は一定しない。40秒という長さの目安として使う) |
| 「いつ戻るか」を決めなくてよい | 再開の一番の壁は「今戻ろうか、もう少し後にしようか」という小さな決断。戻る時刻をツールが先に決めておくと、決断の負担がなくなり、先延ばしが起きにくい | 実行意図(if-then 計画)。決断の回数を減らすと着手しやすい |
| 中身は本人に任せる | 深呼吸、お茶、メモの整理、ぼんやり、何をしてもよい。指示されないので反発が起きにくく、自分で決めた感覚が残る | 自己決定理論(自律性)。09章 §9.3「指示しない」と両立する |
| 毎回同じ形の儀式になる | 同じ合図・同じ長さを繰り返すと、「この画面が出たら戻る」という習慣の合図になる。儀式には不安を下げる効果もある | 習慣の形成(合図→行動)。儀式と不安の低下(Brooks ら 2016) |
| 割り込みを閉じた後に出る | 宿題を外に預けてから(§3)ガイドに入るので、割り込みのことが頭に残りにくい | 注意残余(Leroy 2009)、未完了の目標は計画で静まる(Masicampo & Baumeister 2011) |

#### 1.1.2 気をつける点と手当て

| 懸念 | 起きること | 手当て(設計に入れる) |
|------|-----------|---------------------|
| 時間に追われる感じ | 秒の数字が大きく減っていくと、焦りが出てストレスになる | 秒の数字は小さくし、主役は**ゆっくり満ちていく輪**にする。音は鳴らさない。最後の数秒に点滅などの演出をしない |
| まだ終わっていないのに切り替えられる | 返信を打っている途中で画面が変わると、強い反発(心理的リアクタンス)が起きる | **[+30秒]** と **[今すぐ戻る]** のボタン。時間切れの瞬間に他のアプリでキーを打っていたら、フォーカスは移さず、ガイドを閉じるだけにする |
| 短い割り込みでも毎回出る | 30秒の質問のたびに40秒待たされると、すぐに煩わしくなり、ガイドそのものを切られる | 割り込みが**既定60秒未満**ならガイドを出さない(設定で変えられる) |
| 「集中しましょう」が説教に聞こえる | 言い方次第で、指図・評価に感じる人がいる | 見出しは事実(「元の作業に戻ります」)、一言だけ誘いかけ(「40秒で、元の作業に集中しましょう」)。誘いかけの文は設定で変えられる。§8 Q2 |
| フォーカスを奪う | ガイドの表示中にフォーカスが移ると、打っている文字が別の場所に入る | ガイドはフォーカスを奪わない(WS_EX_NOACTIVATE)。時間切れで元の作業ウィンドウを前面にするのは、キー入力が無いときだけ |
| 慣れて効かなくなる | 毎回同じだと見なくなる | 慣れて見なくなっても、「時間で戻る」という仕組み自体は働く。中身を変えて気を引く演出はしない(落ち着きを優先) |

### 1.2 D7 中断ボタンのアイコン — 中断の心理的な障壁をなくす

「中断」には、失敗・負け・損のイメージがある。押すのをためらうと、記録されないまま割り込みに入り、戻る手がかりが残らない。障壁を下げるため、次の5点を組み合わせる。

| 方針 | 内容 | 根拠 |
|------|------|------|
| 意味づけを変える | アイコンは**しおり**(本に挟むリボン)。「やめる」ではなく「**ここに印を付けて、ちょっと離れる**」。文言は「割り込み対応」。割り込み対応も正当な仕事として扱い、「中断」「停止」という言葉はボタンに使わない | フレーミング効果。損のイメージを避ける |
| 覚えておくのはツールの仕事 | 押した直後に一言「しおりを挟みました。F9 で戻れます」を2秒だけ出す。「忘れても大丈夫」という安心が、押すことへの抵抗を下げる | 認知的オフロード(Risko & Gilbert 2016): 外部に預けられると分かっていると、人は安心して手放せる |
| 1回押すだけ | 入力も確認も求めない(今の F9 と同じ)。押し間違えても、もう一度押せば元に戻る(取り消し自由) | 行動のハードルは手間の数で決まる(Fogg の行動モデル: 能力 = 簡単さ) |
| 怖くない色と形 | 赤・橙・警告の形を使わない。青緑の落ち着いた色(03章 §3.4.1)。割り込みアプリに滞在中だけ、少し目立たせる(今の 09章 §9.4.4 と同じ) | 警告色は「悪いことをしている」という感覚を生む |
| いつでも同じ場所に | 通常表示・コンパクト表示・トレイのメニューのどこからでも押せる。位置を変えない | 迷わないこと自体が障壁を下げる |

戻るときのボタンは、しおりから矢印が出るアイコンで「**元の作業へ  F9**」とする(今の「再開  F9」)。

## 2. 全体の流れ

```
[作業中] ──しおり(F9)──▶ [割り込み対応中] ──F9──▶ (A) 出口カード ──Enter──▶ (B) 再入場ガイド 40秒 ──時間切れ──▶ [作業中]
   │                          │                      │  完了 / 宿題あり          │ [今すぐ戻る] [+30秒]
   │                          │                      │                         └ 60秒未満の割り込みなら出さない
   └─F10 棚上げ ─────────────┴──────────────────────┴──▶ (C) 宿題リスト(ローカルDB、タスクをまたいで残る)
```

- F9 を2回続けて押すと「完了」で閉じる(出口カードで F9 = Enter)。急いでいるときの手間を最小にする。
- 出口カードで Esc を押すと、割り込み対応中に戻る(まだ終わっていなかった場合)。
- 今の復帰カード(S-11)は、(B) の再入場ガイドに統合する(§4.3)。

## 3. (A) 出口カード — 割り込みを閉じる(新 S-11a)

### 3.1 画面

```
┌ 割り込みを閉じる ──────────────────────────┐
│ 割込み作業 ▾                         12分   │ ← カテゴリ(前回使ったもの)・対応時間
│ 件名 [ A社 旧版の設定方法の問い合わせ      ] │ ← 任意
│ ◉ 完了   ○ 宿題が残る                        │
│ ┌ 宿題 ──────────────────────────────┐ │ ← 「宿題が残る」のときだけ開く
│ │ [ 来週の版で直るか確認して返信         ] │ │
│ │ 期限: [今日] [明日] [日付…] [なし]       │ │
│ └────────────────────────────────┘ │
│ ☑ 割り込みで開いたウィンドウを片付ける(5)   │ ← 既定 ON。最小化するだけ(閉じない)
│                   [閉じて元の作業へ  Enter]  │
└───────────────────────────────────┘
```

- **入力しなくても Enter 1回で閉じられる**(完了・件名なし)。書くのは宿題が残るときだけ。
- 開くのは利用者が F9 / [元の作業へ] を押したとき。利用者の操作で開くので、ポップアップを出さない方針(09章 §9.3)に反しない。入力のためにこの時だけフォーカスを取る(メモ入力ウィンドウと同じ扱い)。
- 置き場所: 通常表示ならミニパネルのすぐ下、コンパクト表示ならコンパクト表示のすぐ下、トレイ格納中なら画面の中央上。通常表示に戻す必要はない(独立した小さなウィンドウ)。画面共有から除外する。
- カテゴリのプルダウン: タスクのプルダウン(S-02)と同じ部品。新しい名前を打てば追加、行の右クリックで「一覧から外す」。最近使った順。既定は「割込み作業」。
- 件名は任意。後で振り返りの「よく来る問い合わせ」(前回案 ⑦)に使える。
- 「宿題が残る」の文言は、新しいメンバーにも分かるよう「あとでやることが残る」も候補(§8 Q3)。
- ウィンドウの片付け: 今の復帰カードの [作業画面に戻す] と同じ処理(割り込み中に開いた・前面に出たウィンドウを最小化し、中断前の作業ウィンドウを元の配置で前面に戻す。F-03)。宿題には、そのとき片付けたウィンドウの一覧(プロセス名・タイトル)を付けておく(0.13A で「宿題を開く」ときの手がかりにする。ウィンドウの復元はしない)。

### 3.2 割り込み対応中にできること(変更なし)

- F10 = 元の作業の再開メモ(どこまで / 次の一手)。今のまま。
- 割り込み対応中に F10 の再開メモを書いていなければ、出口カードに「次の一手」の1行を出す案もあるが、カードが重くなるので入れない(再入場ガイドに次の一手を表示するだけ)。

### 3.3 例外の場面

| 場面 | 扱い |
|------|------|
| 割り込み対応中にタスク完了・あとで続ける・アプリを閉じる | 出口カードは出さない。割り込みは「閉じられなかった」(outcome = `unclosed`)として記録する。宿題が残っているなら、利用者がトレイのメニューから宿題を追加できる |
| 離席の問いかけで [はい](割り込みに分類し直し) | 出口カードを出す(カテゴリ・宿題を記録できるように)。再入場ガイドは、離席時間が60秒以上なので出る |
| タスクを始めていないときの割り込み | 今回は対象外(割り込みの記録は実行中のタスクに付くため)。宿題だけは、トレイのメニュー「宿題を追加」からいつでも書ける |
| ホットキー F9 が使えないとき | ミニパネル・コンパクト表示・トレイのメニューのボタンで同じことができる |

## 4. (B) 再入場ガイド — 40秒で元の作業へ(新 S-11b)

### 4.1 画面

```
            ┌───────────────────────────────┐
            │  元の作業に戻ります                         │
            │  開発計画書作成 ─ ② 概略仕様の確認           │
            │  次の一手: 3章の非機能要件から読む           │
            │                                ╭───╮      │
            │  40秒で、元の作業に集中しましょう │ ◔ │ 0:31 │ ← 満ちていく輪。数字は小さく
            │                                ╰───╯      │
            │                [今すぐ戻る]  [+30秒]         │
            └───────────────────────────────┘
               ↑ 後ろには、元の作業のウィンドウが元の配置で出ている
```

- 出口カードを閉じた瞬間に、元の作業ウィンドウを前面に戻し(「片付ける」が ON のとき)、その上にガイドを重ねる。利用者の言う「元の作業のウィンドウを表示」は、**実物のウィンドウを元の配置で前面に出す**ことと解釈した(縮小画像ではなく)。§8 Q1。
- ガイドは**フォーカスを奪わない**半透明のカード(WS_EX_NOACTIVATE、常に最前面)。作業ウィンドウの中央上寄りに置く(作業ウィンドウが無ければ画面の中央)。画面共有から除外する。
- 表示する内容: 元のタスク名とサブタスク、次の一手(無ければどこまで、どちらも無ければ出さない)、誘いかけの一言、残り時間の輪。
- 時間の使い方は書かない(本人に任せる。D3)。初回だけ、小さく「この時間の使い方は自由です(深呼吸、お茶、メモの整理など)」を出す(新しいメンバー向け。§8 Q2)。
- 音は鳴らさない。

### 4.2 時間切れ・操作

| 操作 / 状況 | 動き |
|-------------|------|
| 時間切れ | ガイドを0.5秒でフェードして閉じる。直前2秒に他のアプリでキー入力が無ければ、元の作業ウィンドウ(中断前に最後に使っていたもの)にフォーカスを移す。入力中なら移さない |
| [今すぐ戻る] / Esc | すぐに時間切れと同じ動き |
| [+30秒] | 残りに30秒足す(何回でも) |
| 割り込みが短い | 割り込みの時間が `reentry_guide_min_interrupt_sec`(既定60秒)未満ならガイドを出さず、すぐ作業中に戻る |
| ガイド中に F9 | 新しい割り込みとして扱う(ガイドを閉じて、割り込み対応中に入る) |
| コンパクト表示・トレイから | ガイドは同じように出る。時間切れ後は、割り込み前の表示(コンパクト表示 / トレイ)に戻る |

### 4.3 今の復帰カード(S-11)との関係

- 再入場ガイドが、復帰カードの「次の一手・どこまで・中断時間」を引き継ぐ。ガイドが閉じたあと、ミニパネルの中に復帰カードの残り(確認した資料・作業トレイ)を畳んだ状態で残し、クリックで開けるようにする。
- ガイドが出ない場合(短い割り込み、設定で OFF)は、今の復帰カードをそのまま出す。

### 4.4 時間の数え方

- 割り込みの一時停止は、出口カードを閉じた時点で終わる。ガイドの時間は**作業時間に含める**(再入場も作業の一部)。ガイドの区間は `reentry` として記録し、後で「復帰にかかった時間」(psychology-ideas.md I-08)を出せるようにする。
- 記録: ガイドの表示時刻、閉じ方(timeout / now / extend の回数)、閉じたあと作業ウィンドウで最初に操作するまでの時間。

## 5. (C) 宿題リスト(新 S-12)

### 5.1 何が入るか

| 入口 | 内容 |
|------|------|
| 出口カードの「宿題が残る」 | 宿題の文、期限、カテゴリ、件名、元のタスク、片付けたウィンドウの一覧 |
| 作業中の F10(棚上げ) | 今の棚上げリスト(09章 §9.4.2a)を宿題リストに統合する。期限なし、カテゴリは既定 |
| 手で追加 | トレイのメニュー・宿題リストの画面の「追加」。タスクを始めていなくても書ける |

宿題は**タスクの実行をまたいで残る**(今の棚上げは実行ごと)。完了にするか、消すまで残る。

### 5.2 見せ方(ポップアップは出さない)

- ミニパネルとコンパクト表示に、小さく「宿題 3」(期限が今日・過ぎたものがあれば「宿題 3 ・今日 1」、柔らかい琥珀)。クリックで宿題リストを開く。
- 期限の知らせは**区切りのときだけ**: サブタスクの完了時、タスク完了時(S-06)、開始準備(S-02)の画面。作業の途中には出さない。
- タスク完了時(S-06)に、この実行で増えた宿題を一覧で出す(今の棚上げリストの表示を置き換え)。

### 5.3 画面

```
┌ 宿題 ─────────────────────────────── 追加 ┐
│ 今日まで                                              │
│ ☐ 来週の版で直るか確認して返信   割込み作業  A社… 今日 │
│ 期限なし                                              │
│ ☐ 社内ツールの手順をまとめる     割込み作業      3日前 │
│ ─ 完了(直近7日) ▸                                   │
└──────────────────────────────────────┘
```

- 並び: 期限切れ → 今日 → 明日 → 日付順 → 期限なし(古い順)。
- 行の操作: チェックで完了、ダブルクリックで編集(文・期限・カテゴリ)、右クリックで「削除」「元の割り込みの記録を見る」。
- 完了したものは7日間だけ折りたたんで見せる(取り消しができるように)。
- 開き方: トレイのメニュー「宿題」、ミニパネルの「宿題 n」、開始準備の画面のリンク。画面共有から除外する(顧客名が入るため。D5)。

### 5.4 0.12A と 0.13A の分け方(提案)

- **0.12A**: 中断ボタンのアイコン、出口カード、割り込みカテゴリ、再入場ガイド、宿題の**保存**と、タスク完了時の一覧、トレイのメニューからの簡単な一覧(完了にする・削除だけ)。
- **0.13A**: 宿題リストの画面の仕上げ(編集、期限の並び、「宿題 n」の表示、区切りでの知らせ、手で追加、F10 棚上げの統合)。

## 6. データと内部の設計

### 6.1 Core(純粋・テストする)

| 追加 | 内容 |
|------|------|
| `Cmd.InterruptClose` → `Ev.InterruptClosed` | 項目: category、title、outcome(`done` / `followup` / `unclosed`)、followup_id、tidy(yes/no)、interrupt_sec。続けて今の `Ev.Resumed(reason=interrupt)` を出す。宿題そのものは DB が正(§6.2)。イベントは記録と再生のため |
| `Cmd.ReentryEnd` → `Ev.ReentryEnded` | 項目: how(`timeout` / `now` / `skipped_short` / `off`)、shown_sec、extend_count |
| `ReentryPolicy.Decide(interruptSec, settings)` | ガイドを出すか・何秒か。`ReentryPolicy.MayMoveFocus(lastKeyInputAgo)` = 時間切れでフォーカスを移してよいか |
| `FollowupOrder` | 宿題の並び順、期限の区分(期限切れ / 今日 / 明日 / 先 / なし)、「宿題 n ・今日 m」の文言 |
| シナリオDSL | `interrupt_close category=… outcome=followup followup="…"`、`expect reentry …` を追加。割り込み→閉じる→ガイド→作業中、の流れをシナリオで確かめる |

### 6.2 Storage(SQLite スキーマ v6)

```sql
CREATE TABLE interrupt_categories(
  id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE,
  archived INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, last_used_at TEXT NULL);
-- 初期データ: '割込み作業'

CREATE TABLE interrupt_records(           -- 出口カードを閉じたとき、すぐに書く(異常終了に強くする)
  id INTEGER PRIMARY KEY, run_id TEXT NULL, started_at TEXT NOT NULL, ended_at TEXT NOT NULL,
  category_id INTEGER NULL REFERENCES interrupt_categories(id),
  title TEXT NOT NULL DEFAULT '', outcome TEXT NOT NULL, reentry_how TEXT NULL, reentry_sec REAL NULL);

CREATE TABLE followups(
  id INTEGER PRIMARY KEY, created_at TEXT NOT NULL, source TEXT NOT NULL,   -- interrupt / defer / manual
  text TEXT NOT NULL, due_date TEXT NULL, status TEXT NOT NULL DEFAULT 'open', -- open / done / deleted
  done_at TEXT NULL, category_id INTEGER NULL, interrupt_id INTEGER NULL,
  task_name TEXT NULL, windows_json TEXT NULL, updated_at TEXT NOT NULL);
```

- 削除は `status='deleted'`(論理削除)。物理削除は、設定のデータ整理でまとめて行う。
- 期限は日付だけ(時刻は持たない)。「今日」「明日」はその場で日付に直して保存する。

### 設計から変えた点・決めた細部

- 押した直後の2秒の一言(「しおりを挟みました」)は、消える表示ではなく、対応中ずっと出ている縁の文言(「しおりを挟みました。対応が済んだら F9 で元の作業へ(F10 で再開メモ)」)にした。見落としても、いつでも読める方が安心につながるため。
- 期限の初期値は「期限なし」(書かずに閉じられるように)。「日付」を選んだときだけ日付の欄を出す。
- 元の作業ウィンドウを前に出す操作は、出口カードがアクティブなうちに行う(閉じた後では Windows がフォーカスの移動を許さないことがある)。片付け(最小化)の ON/OFF とは関係なく、元の作業ウィンドウは前に出す。練習モードでは片付けは動かない(今までと同じ)。
- 出口カードの × は「まだ対応を続ける」と同じ。タスクの終了・中断・アプリを閉じるときに開いていた出口カードは閉じる(割り込みは閉じない扱いで、記録は付かない)。
- ダイアログ: `MessageBox` を `FcDialog`(`Chrome.cs`)に置き換え、コードで作るウィンドウには `Chrome.Frame` で共通のタイトル帯を付けた。閉じるときの確認は、ボタンを「閉じない / 終了して閉じる / 中断して閉じる」にし、Enter の既定を記録を失わない「中断して閉じる」にした(以前は「はい」= 終了)。ダイアログは Owner を設定せず、位置だけ元のウィンドウの上に合わせる(閉じる途中のウィンドウを Owner にすると WPF が例外にするため)。
- 0.13A に回したもの: 一覧での編集・手での追加、F10 棚上げのあとでやることへの統合、区切り(サブタスク完了)での期限の知らせ。

### 確認したこと

- テスト145件(ReentryPolicy・Followups・v6 の移行と保存・シナリオ `interrupt_close_reentry.txt`)。
- 実アプリの自動操作(UI Automation と WM_HOTKEY。合成キー入力なし。保存先は隔離): F9 で「元の作業へ」に変わる → F9 で出口カード → カテゴリ・件名・あとでやること・明日を入れて閉じる → ガイドが元の作業ウィンドウの上に出て(anchored=yes)、5秒で消える(how=timeout)→ ミニパネルに「あとでやること」。F9 → F9 → F9 で「完了」で閉じてガイド → ガイド中の F9 で新しい割り込み。出口カードの「まだ対応を続ける」で対応中のまま。閉じる確認(新しいダイアログ)の「中断して閉じる」で終了。タスク完了 → 振り返り(新しいダイアログ)→ 開始準備に戻る。DB に v6 の表・カテゴリ・割り込みの記録(ガイドの閉じ方と秒数)・あとでやること(期限 = 明日)が入ることを確認。
- 見た目: `prototype/ui_render_probe` で、ボタン・出口カード(完了 / あとでやること / エラー)・ガイド・一覧・ダイアログを PNG にして確認。
- 未確認(利用者の実機で): 実際の F9 キーでの操作感、ガイドの40秒の長さと見え方、ガイドが他のアプリの入力を邪魔しないか、2枚のモニタでのガイドの位置、片付け(練習モードを外したとき)。
