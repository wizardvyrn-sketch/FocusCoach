## 0. 凡例

- 重要度 **A**: 第一弾で必ず直す(データの欠落・誤り、利用者の作業を壊す、主目的の「中断からの復帰」に直結)。**B**: 第一弾で直したい。**C**: 後回し可。
- 根拠 **再現**: クラウドでシナリオを実行して再現した。**コード**: コードを読んで判断した。**要実機**: Windows 実機で確かめないと確定できない。
- 「仕様」列が ○ の項目は、コードの前に `docs/spec/` の該当章を更新する。

## 4. 仕様書に反映する事項(コードより先に行う)

1. 09 §9.4.1: ⚡はワンクリックで一時停止し、メモは後から付けられる(R-01)。種類の選択と音声メモ(R-05、R-06)。
2. 09 / 05 F-15: 離席・ロック・スリープから戻ったときに、その区間を割り込みに分類し直せる(R-04、R-16、R-17)。
3. 04 / 05 F-15 / 09 §9.7: 状態 `suspended`(後日再開)と、日をまたぐ実行の集計(R-18)。
4. 05 F-11 / 04: サブタスクの時間からアイドルを除く。一時停止中の切り替えは数えない。割り込みアプリのウィンドウは、作業中に開いてもオンタスクにしない(R-15、R-21、R-22)。`formula_version=2`。
5. 08 §8.3: `session_resumed`、`idle_reclassified`、`ws_*` の記録、異常終了後の空白を `crash` 理由の一時停止にすること(R-08、R-11)。
6. 03 S-04: 画面共有から除外する、片手で押せるホットキー、メモ入力用の小ウィンドウ、ミニパネル位置の保存(R-02、R-03、R-20、R-25)。

**R-46 リモートデスクトップ(A、要実機)**

- 前面がリモートデスクトップ接続(`mstsc.exe`)のとき、接続先の中のウィンドウは見えない。接続先で作業している時間を、オンタスクかどうか判定できない。
  - 対策: `mstsc.exe` を「タスクで使うアプリ」に指定できるようにする(R-43)。ウィンドウのタイトル(接続先の名前)ごとに、オンタスク/オフタスクを指定できるようにする。
- 全画面のリモートデスクトップでは、キー入力が接続先へ送られる。**F9〜F12 のホットキーがローカルの FocusCoach に届かない可能性がある**。全画面のときは、ミニパネルが接続画面の下に隠れる可能性もある。
  - 対策: 実機で確認する(L-21)。届かない場合は、低レベルのキーボードフック(`WH_KEYBOARD_LL`)を試す。それでもだめなら、全画面のときはミニパネルのボタン(マウス)で操作する前提にする。
- 「業務PCに外から接続して、業務PCの上で FocusCoach を使う」形もあり得る。その場合は、接続・切断(WTS のセッションイベント)を離席として扱う必要がある。
  - どちらの形か、利用者に確認する(§7.4)。

**R-03 割り込みキーの既定(確定)**

| キー | 動作 | 補足 |
|------|------|------|
| F9 | 割り込み ⇄ 再開(トグル)。押した瞬間に一時停止する(R-01)。もう一度押すと再開し、復帰カードを出す | 片手で押せる。Excel の手動再計算(F9)は使えなくなる |
