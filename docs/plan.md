## 注意点・決定事項

### 利用者・業務の前提
- 利用者の課題は「気が散る」ことではなく、割り込み(約1時間に1回、主に Teams のチャット)で中断した後に戻れなくなること。作業中のポップアップと、作業の順序の指示は避ける(画面隅の色の変化までが許容範囲)。詳細は 09章 §9.2。
- Outlook の予定表は顧客名を含むため使用禁止。Webカメラは使わない。画面画像などを一般の Web サービスへ送らない(Claude の Team プランは許可されている)。
- リモートデスクトップは、(a) 業務PCから他へ接続 = サーバー管理のタスクなので管理対象外、(b) 外から業務PCへ接続 = 切断を離席(remote)として扱う。
- 実機の記録データ(DB / JSONL / 音声 / ログ)には機密が含まれうるため、`.gitignore` で除外している。テストデータは架空のものにする。

### クラウド(Linux)とローカル(Windows)の違い
- WPF は Linux の SDK ではビルドできない。クラウドでは `dotnet test FocusCoach.cloud.slnf`(App を除外)と `scripts/check-app-codebehind.sh`(コードビハインドの型チェック)を使う。後者は MainWindow.xaml の `x:Name` 付き要素の型からスタブを作るので、`System.Windows.Controls` 以外の型に名前を付けたら、スタブの `using` に名前空間を足す(`Ellipse` のため `System.Windows.Shapes` を追加済み)。このスクリプトは Windows では動かない。Windows は本物の WPF ビルドで確認する。
- **Windows でしか出ない不具合に注意**: 書き込み中の JSONL を読むには `FileShare.ReadWrite` が要る。テストのファイルは、ハンドルを閉じてから削除する。
- Linux の `Path.GetFileName` は `\` を区切りにしない。Core で Windows 形式のパスを扱うときは `Reducer.FileNameOf` のような自前の関数を使う。
- `FocusCoach.sln` は App を含む(クラウド用の `.slnf` は除外)。実機確認の前に、exe の更新時刻を確かめる(2026-10-04 に古い exe を動かしていたことがある)。
- クラウドとローカルで同じ番号のバージョンを付けないよう、作業の前に `git pull` する(0.6A が重なり、統合時に 0.7A へ振り直した)。0.7B からは SessionStart フックの `scripts/session-sync.sh` が自動で確認する。ルールは CLAUDE.md「Cloud ⇄ local sync」。

### 実装の決まりごと
- Core のイベントループは「1件ずつ順番に処理」を保証する。同じ OS スレッドで走ることは保証しない。結果は購読者の呼び出しより前に返るので、テストで購読者の副作用を待つときは、もう1件コマンドを送ってから確かめる。
- 監視由来のコマンドの印は `origin=monitor`(`source` は資料の記録方式で使うので衝突する)。OS のメッセージ(スリープなど)は、受けた時刻をコマンドに付けて Post する。
- 実行が閉じた後に届く操作は、`Loop!` で落とさず「拒否」にする(`CoreHost.SendAsync`)。
- WPF: `Closing` イベントの中で `Close()` を呼ばない(イベントを抜けてから閉じる)。モーダルにしたいメッセージボックスは `MessageBox.Show(this, …)`(所有者なしだと後ろに回り、その間パネルを操作できてしまう)。
- 色・書体は `App.xaml` の名前付きリソースに集約している(`Bg`、`Accent`、`Warn` など)。コードビハインドからは `Res("名前")`、コードで作るウィンドウは `Theme.Apply(this)` で当てる。画面ごとに色を直接書かない。
- 持ち運び版(0.9A): `dotnet publish -r win-x64 --self-contained`(フォルダ形式。WPF はトリミング・単一ファイル化に向かない)。E:\ は容量が 500MB しかなく、約 160MB を使う。署名していないので、配布先で SmartScreen の警告が出うる。`robocopy /MIR` で置き換えるのは `app\` だけで、持ち運び用の `data\` は触らない。デプロイ用のファイルは `deploy/`、手順は `deploy/README.txt`。
- 開始準備のタスク欄は入力もできる ComboBox。文字の変化は `TextBoxBase.TextChangedEvent` を AddHandler で拾う(一覧から選んだときも届く)。手順は `_stepsCategory` が変わったときだけ読み直すので、同じタスクのまま手順エディタで直した内容は消えない。
- WPF の Popup(プルダウンの一覧など)は別ウィンドウなので、画面共有からの除外を個別に掛ける(`DropDownOpened` で Popup の HwndSource に `ExcludeFromCapture`。0.8A で確認済み: 0x11)。新しく Popup・ToolTip にタスク名やメモを出すときも同じ扱いにする。
- WPF の `Closing` イベントの内側では、`Close()` だけでなく `Show()` も例外になる(隠れているウィンドウを戻すときなど)。イベントを `e.Cancel = true` で抜けてから Dispatcher で戻し、閉じる処理をやり直す(コンパクト表示から閉じるときに実際に起きた。0.10A)。
- 透過ウィンドウ(`AllowsTransparency`)は作った後に切り替えられないので、透過が要る表示は別ウィンドウ(`CompactHud`)にする。クリック透過は拡張スタイル `WS_EX_TRANSPARENT | WS_EX_LAYERED`、フォーカスを奪わないのは `WS_EX_NOACTIVATE`。クリック透過中はマウスのイベントが来ないので、カーソルの位置は `GetCursorPos` で直接見る。判断は Core の `HudPolicy`(テスト済み)。
- 隠れているウィンドウにも `WM_HOTKEY` は届く。自動操作から F8 を試すときは、疑似キー入力ではなく、メインのウィンドウ(隠れていても可)に `WM_HOTKEY`(wParam=3)を送る。`Process.CloseMainWindow` はコンパクト表示の間は HUD を指すので、閉じる要求は隠れたメインに直接 `WM_CLOSE` で送る。
- 隠した(`Hide()`)ウィンドウは、`Left`/`Top` が NaN、`ActualHeight` が 0 になることがある。隠す前に位置とサイズを控え(`RememberBounds`)、戻す・保存するときは控えを使う(0.11A)。コンパクト表示の左上起点の計算も、この控えを使う。
- タスクトレイは `System.Windows.Forms.NotifyIcon`(`TrayIcon.cs`)。WPF の App に `UseWindowsForms` を足すと、`Application`・`MessageBox`・`Button` などの名前が重なるので、暗黙の using(`System.Windows.Forms`・`System.Drawing`)は外してある。WinForms の型は完全修飾で書く。クラウド用の型チェック(`scripts/check-app-codebehind.sh`)にも WindowsForms の参照を足した。
- トレイのアイコンの有無は、このPC(Windows 11)では外から数えられなかった(UI Automation にも、従来型の `ToolbarWindow32` にも出ない)。アプリのログ `UI: tray icon created`(例外なら `tray icon failed`)と、終了時に `NotifyIcon.Visible=false` にしていることで担保し、見え方は利用者の目で確認する。
- 2つ目の起動は、名前付きイベント(`Local\FocusCoach.Show`)で起動中のアプリに合図する。[仮案-31](案内して終了)は 0.11A で置き換えた。
- 割り込みの出口(0.12A): 対応中の F9 は出口カード、カードの表示中の F9 は Enter と同じ、ガイドの表示中の F9 は新しい割り込み。元の作業ウィンドウを前に出すのは、出口カードがアクティブなうちに行う(閉じてからだと Windows がフォーカスの移動を許さないことがある)。ガイドの時間切れでは、直前2秒に入力があればフォーカスを移さない(`ReentryPolicy.MayMoveFocus`)。
- ダイアログは `FcDialog`(`Chrome.cs`)を使い、`MessageBox` は使わない(起動前・異常終了時の予備だけ)。コードで作るウィンドウは `Chrome.Frame` でタイトル帯を付ける。`FcDialog` は Owner を設定しない(閉じる途中のウィンドウを Owner にすると WPF が例外にするため。位置だけ合わせる)。自前のダイアログのボタンは UI Automation の Invoke で押せる(Win32 のメッセージボックスのボタンは Pane として見え、Invoke できなかった)。
- スキーマ v6 の移行は `CREATE TABLE IF NOT EXISTS`(古い版から上げるテストが user_version だけ戻すため、表が残っていても壊れないように)。
- 確認用の設定: `ReentryGuideSec` を 5、`ReentryGuideMinInterruptSec` を 0 にすると、ガイドの流れを短時間で確かめられる(隔離した保存先の settings.json に書く)。
- PowerShell 5.1 でスクリプトを実行するときは、日本語を含むなら UTF-8 の BOM を付ける(無いと文字化けして構文エラーになる)。
- 多言語化(0.13A): 画面に出る日本語は `Core/Strings/ja.json`・`en.json` に置き、コードは `Loc.T("キー", 引数)`、XAML は `{loc:T キー}`。**日本語を直書きするとテストが落ちる**。新しい文言は両方のファイルに足す。ホットキーの名前は設定から作って `{0}` に入れる(文言に F9 を直書きしない)。確認用の自動操作は、表示名ではなく `AutomationId` で探す(言語で表示名が替わる)。
- 既定のカテゴリは内部名 `割込み作業` で保存し、表示は `InterruptCategories.Display` / 保存は `Canonical`。`ReentryGuideMessage` は未設定(null)で言語ごとの既定文、0.12A で保存された日本語の既定文も未設定として扱う。
- トレイのメニューの文言は `TrayIcon.Refresh()` で作り直す(言語・ホットキーの名前が替わったとき)。メニューの左の余白を出していないので、現在の言語の印は ● を文字に付けている。
- 書体は `LangFonts`(`UiFont` を `DynamicResource` で差し替え)。コードで作るウィンドウは `Theme.Apply` が開くときの言語で決める。
- 起動画面(0.14A)は `SplashWindow`(コードで組む。クラウドの型チェックが XAML を扱えないため)。書体は `pack://application:,,,/FocusCoach;component/` で読む(component 指定にしないと、描画の確認ツールなど別の exe から読めない)。題名は `FocusCoach Boot`(本体の `FocusCoach` と分ける。題名でウィンドウを探す確認スクリプトのため)。本体を出した時点で `Application.MainWindow` を本体に差し替え、`ShutdownMode = OnMainWindowClose` にする。
- 言語の前提: 利用者はメインの言語だけで使う(日本語の利用者は日本語に英語が混ざりうる、英語の利用者は英語だけ)。
- 再開メモの空の行は「変更しない」扱い(どちらか1行だけ書き直せる)。行を消して空にすることはできない。
- シナリオの DSL は 08章 §8.2。時刻は `HH:MM`(`00:12` = 12分)、サブタスク番号は 1 始まり。

### 実機確認のやり方
- 疑似キー入力は使わない。自動操作は UI Automation と Win32 で行う(`prototype/ui_close_flow_probe.ps1`)。標準のメッセージボックスは UIA で中身が取れないので、子ウィンドウを列挙して `BM_CLICK` で押す。
- 見た目は `prototype/ui_render_probe`(RenderTargetBitmap で PNG にする)で確認する。画面のキャプチャは、画面共有からの除外で黒くなり、PC がロック中だと失敗する。除外を外したいときだけ `FOCUSCOACH_ALLOW_CAPTURE=1`(開発用)。
- 試用は `FOCUSCOACH_DATA` で保存先を分ける。
- `.ps1` は `powershell -ExecutionPolicy Bypass -File` で実行する。日本語を含む `.ps1` は BOM 付き UTF-8 で保存する(Windows PowerShell 5.1 が Shift-JIS として読むため)。
- 業務PCは USB メモリへ書き込めないため、`workpc_check.ps1` は結果を画面に OK/NG だけ表示する。
